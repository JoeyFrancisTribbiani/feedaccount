# feedaccount 自动发布架构重构计划

> **For Hermes:** 使用 subagent-driven-development skill 逐任务实现本计划。

**目标：** 将自动发布配置从「按达人」重构为「按矩阵」组织，去掉 `creator_profile_bindings` 表，实例绑定统一走 `matrix_profiles`（矩阵→实例 1对1），调度器从矩阵维度查 profileId 与 daily_limit。

**架构：** 矩阵为顶层组织单位。一个矩阵绑一个指纹浏览器实例（`matrix_profiles` 1对1），一个矩阵下每个平台只有一个账号（`matrix_accounts`，`UNIQUE(matrix_id, platform)`），同矩阵不同平台账号登录同一浏览器实例。矩阵账号选对标达人（`matrix_account_creators` 保留）。达人视频可发到不同矩阵的不同平台账号。自动发布配置按矩阵存储。

**技术栈：** Node.js ESM (`node:sqlite` `DatabaseSync`)、原生 `node:http` 路由、前端原生 JS (public/app.js + index.html)

### 数据流

```
达人发新视频 → 调度器监控 → 找到选了该达人的所有矩阵账号(macs)
→ 找到矩阵账号所属矩阵 → 找矩阵绑定的实例(matrix_profiles.profile_id)
→ 找矩阵自动发布配置(matrix_auto_publish_config) → 创建 pipeline 任务
→ 混剪 → 排期(查 daily_limit 从矩阵配置) → 发布到该 profile
```

### 关键约束说明

| 约束 | 实现 |
|------|------|
| 一个矩阵绑一个实例 | `matrix_profiles` 加 `UNIQUE(matrix_id)` 约束，1对1 |
| 一个矩阵下每个平台只有一个账号 | `matrix_accounts` 已有 `UNIQUE(matrix_id, platform)` |
| 同矩阵不同平台账号登录同一浏览器实例 | 都通过 `matrix_profiles` 查到同一个 `profile_id` |
| 矩阵账号选对标达人 | `matrix_account_creators`（方向：矩阵账号→达人） |
| 一个达人视频可发到不同矩阵的不同平台账号 | 调度器通过 `matrix_account_creators` 反查所有选了该达人的矩阵账号 |

## 2. 数据库变更

### 2.1 新建表

#### `matrix_auto_publish_config`（按矩阵自动发布配置，替代 `creator_auto_publish_config`）

```sql
CREATE TABLE IF NOT EXISTS matrix_auto_publish_config (
  matrix_id TEXT PRIMARY KEY,
  enabled INTEGER DEFAULT 0,
  preset_id TEXT,
  daily_limit INTEGER DEFAULT 3,
  monitor_interval_hours INTEGER DEFAULT 6,
  last_monitor_at TEXT,
  publish_time_slots TEXT,
  ratio TEXT DEFAULT '9:16',
  hashtags_json TEXT,
  privacy_level TEXT DEFAULT 'public',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (matrix_id) REFERENCES media_matrices(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_matrix_auto_publish_config_enabled ON matrix_auto_publish_config(enabled);
```

> **字段映射（旧→新）：** `creator_id`(PK) → `matrix_id`(PK)；`daily_limit_per_profile` → `daily_limit`（语义不变，每实例每日上限）；`tiktok_username`/`cdp_instance_id` 删除（监控用户名从 `matrix_account_creators`→`remix_creators` 查，实例从 `matrix_profiles` 查）；`matrix_id` 删除（它本身是 PK 了）；其余字段直接搬过来。

### 2.2 改表

#### `matrix_profiles` — 从「多实例」改为「1对1」

```sql
-- 删旧唯一约束（matrix_id, profile_id），加新唯一约束（matrix_id 单列）
-- SQLite 无法直接改约束，需重建表
```

实际操作（在 `database.js` 迁移代码中）：

```js
// 1. 检查旧约束是否存在（matrix_id + profile_id 组合唯一）
// 2. 若旧约束存在，重建表：
CREATE TABLE matrix_profiles_new (
  id TEXT PRIMARY KEY,
  matrix_id TEXT NOT NULL,
  profile_id TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY (matrix_id) REFERENCES media_matrices(id) ON DELETE CASCADE,
  UNIQUE (matrix_id)  -- 关键：1对1，一个矩阵只能绑一个实例
);
INSERT INTO matrix_profiles_new SELECT * FROM matrix_profiles;
DROP TABLE matrix_profiles;
ALTER TABLE matrix_profiles_new RENAME TO matrix_profiles;
CREATE INDEX IF NOT EXISTS idx_matrix_profiles_matrix ON matrix_profiles(matrix_id);
```

> 当前 `matrix_profiles` 为空表（0 行），迁移最安全。

#### `auto_remix_publish_pipeline` — 补全缺失列的 ensureColumn

当前表定义（`database.js:441-454`）**缺少** `source_url` 和 `matrix_id` 列，但调度器 INSERT 语句（`auto-publish-scheduler.js:232-234`）引用了这两列。线上 DB 恰好有这两列（疑似历史手动迁移），但代码里没有对应的 `#ensureColumn`，新库会报错。补上：

```js
this.#ensureColumn("auto_remix_publish_pipeline", "source_url", "TEXT");
this.#ensureColumn("auto_remix_publish_pipeline", "matrix_id", "TEXT");
```

位置：`database.js` 第 617 行后。

### 2.3 删表

#### `creator_profile_bindings`（删除）

实例绑定改走 `matrix_profiles`，此表废弃。

> 线上 DB 仅 1 行数据，迁移后可安全删除。

#### `creator_auto_publish_config`（删除）

### 2.4 迁移脚本（保留现有数据）

在 `database.js` 初始化迁移块中添加（位置：现有 `#ensureColumn` 块之后，约第 600 行）：

```js
// ===== 架构重构迁移：按矩阵自动发布 =====

// 2.4.1 补全 pipeline 缺失列
this.#ensureColumn("auto_remix_publish_pipeline", "source_url", "TEXT");
this.#ensureColumn("auto_remix_publish_pipeline", "matrix_id", "TEXT");

// 2.4.2 新建 matrix_auto_publish_config 表
this.db.exec(`
  CREATE TABLE IF NOT EXISTS matrix_auto_publish_config (
    matrix_id TEXT PRIMARY KEY,
    enabled INTEGER DEFAULT 0,
    preset_id TEXT,
    daily_limit INTEGER DEFAULT 3,
    monitor_interval_hours INTEGER DEFAULT 6,
    last_monitor_at TEXT,
    publish_time_slots TEXT,
    ratio TEXT DEFAULT '9:16',
    hashtags_json TEXT,
    privacy_level TEXT DEFAULT 'public',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (matrix_id) REFERENCES media_matrices(id) ON DELETE CASCADE
  );
  CREATE INDEX IF NOT EXISTS idx_matrix_auto_publish_config_enabled
    ON matrix_auto_publish_config(enabled);
`);

// 2.4.3 迁移 creator_auto_publish_config → matrix_auto_publish_config
//     按 creator_auto_publish_config.matrix_id 聚合（每矩阵取一条配置）
const hasOldConfig = this.db.prepare(
  "SELECT name FROM sqlite_master WHERE type='table' AND name='creator_auto_publish_config'"
).get();
if (hasOldConfig) {
  const oldRows = this.db.prepare(`
    SELECT * FROM creator_auto_publish_config WHERE matrix_id IS NOT NULL
  `).all();

  const ts = nowIso();
  const insertCfg = this.db.prepare(`
    INSERT OR IGNORE INTO matrix_auto_publish_config
      (matrix_id, enabled, preset_id, daily_limit, monitor_interval_hours,
       last_monitor_at, publish_time_slots, ratio, hashtags_json,
       privacy_level, created_at, updated_at)
    VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
  `);

  for (const r of oldRows) {
    // 跳过已迁移的（幂等）
    const exists = this.db.prepare(
      "SELECT matrix_id FROM matrix_auto_publish_config WHERE matrix_id = ?"
    ).get(r.matrix_id);
    if (exists) continue;

    insertCfg.run(
      r.matrix_id,
      r.enabled ?? 0,
      r.preset_id || null,
      r.daily_limit_per_profile || 3,
      r.monitor_interval_hours || 6,
      r.last_monitor_at || null,
      r.publish_time_slots || null,
      r.ratio || '9:16',
      r.hashtags_json || null,
      r.privacy_level || 'public',
      r.created_at || ts,
      r.updated_at || ts,
    );
  }

  // 2.4.4 迁移 creator_profile_bindings → matrix_profiles
  //       按 creator_auto_publish_config.matrix_id 找矩阵，
  //       按 creator_profile_bindings.creator_id 关联
  const hasBindings = this.db.prepare(
    "SELECT name FROM sqlite_master WHERE type='table' AND name='creator_profile_bindings'"
  ).get();
  if (hasBindings) {
    const bindings = this.db.prepare(`
      SELECT cpb.creator_id, cpb.profile_id, cpb.daily_limit, cpb.cdp_instance_id,
             capc.matrix_id
      FROM creator_profile_bindings cpb
      LEFT JOIN creator_auto_publish_config capc ON capc.creator_id = cpb.creator_id
      WHERE capc.matrix_id IS NOT NULL
        AND cpb.profile_id IS NOT NULL
    `).all();

    for (const b of bindings) {
      // 检查该矩阵是否已有实例绑定
      const existing = this.db.prepare(
        "SELECT profile_id FROM matrix_profiles WHERE matrix_id = ?"
      ).get(b.matrix_id);
      if (existing) continue; // 1对1，已有则跳过

      const id = `mp_${Date.now()}_${Math.random().toString(36).substring(2, 7)}`;
      this.db.prepare(
        "INSERT OR IGNORE INTO matrix_profiles (id, matrix_id, profile_id, created_at) VALUES (?, ?, ?, ?)"
      ).run(id, b.matrix_id, b.profile_id, ts);
    }
  }
}

// 2.4.5 matrix_profiles 重建为 1:1 约束（若旧约束仍在）
const mpSchema = this.db.prepare("SELECT sql FROM sqlite_master WHERE type='table' AND name='matrix_profiles'").get();
if (mpSchema && mpSchema.sql.includes("matrix_id, profile_id")) {
  // 旧约束（组合唯一），需要重建为 1:1
  this.db.exec(`
    CREATE TABLE IF NOT EXISTS matrix_profiles_new (
      id TEXT PRIMARY KEY,
      matrix_id TEXT NOT NULL,
      profile_id TEXT NOT NULL,
      created_at TEXT NOT NULL,
      FOREIGN KEY (matrix_id) REFERENCES media_matrices(id) ON DELETE CASCADE,
      UNIQUE (matrix_id)
    );
    INSERT OR IGNORE INTO matrix_profiles_new (id, matrix_id, profile_id, created_at)
      SELECT id, matrix_id, profile_id, created_at FROM matrix_profiles;
    DROP TABLE matrix_profiles;
    ALTER TABLE matrix_profiles_new RENAME TO matrix_profiles;
    CREATE INDEX IF NOT EXISTS idx_matrix_profiles_matrix ON matrix_profiles(matrix_id);
  `);
}

// 2.4.6 旧表保留但标记废弃（不立即删，防止回滚需求）
//   creator_auto_publish_config 和 creator_profile_bindings 保留在 DB 中，
//   代码不再读写。可在后续版本确认无问题后 DROP。
```

> **不立即 DROP 旧表的原因：** 迁移脚本是幂等的，万一迁移有误需要回滚，旧表数据还在。等确认新架构稳定运行后（建议 1 周后），再在迁移代码中加 `DROP TABLE IF EXISTS creator_profile_bindings; DROP TABLE IF EXISTS creator_auto_publish_config;`

### 3.4 database.js 新增 Store 方法

```js
// ===== matrix_auto_publish_config =====

getMatrixAutoPublishConfig(matrixId) {
  const row = this.db
    .prepare("SELECT * FROM matrix_auto_publish_config WHERE matrix_id = ?")
    .get(matrixId);
  if (!row) return null;
  return {
    matrixId: row.matrix_id,
    enabled: row.enabled !== 0,
    presetId: row.preset_id || null,
    dailyLimit: Number(row.daily_limit || 3),
    monitorIntervalHours: Number(row.monitor_interval_hours || 6),
    lastMonitorAt: row.last_monitor_at || null,
    publishTimeSlots: row.publish_time_slots || null,
    ratio: row.ratio || "9:16",
    hashtagsJson: row.hashtags_json || null,
    privacyLevel: row.privacy_level || "public",
    createdAt: row.created_at,
    updatedAt: row.updated_at,
  };
}

upsertMatrixAutoPublishConfig(matrixId, {
  enabled = null, presetId = null, dailyLimit = null,
  monitorIntervalHours = null, lastMonitorAt = null,
  publishTimeSlots = null, ratio = null,
  hashtagsJson = null, privacyLevel = null,
} = {}) {
  const ts = nowIso();
  const existing = this.db
    .prepare("SELECT matrix_id FROM matrix_auto_publish_config WHERE matrix_id = ?")
    .get(matrixId);
  if (existing) {
    const sets = [];
    const params = [];
    if (enabled !== null) { sets.push("enabled = ?"); params.push(enabled ? 1 : 0); }
    if (presetId !== null) { sets.push("preset_id = ?"); params.push(presetId); }
    if (dailyLimit !== null) { sets.push("daily_limit = ?"); params.push(dailyLimit); }
    if (monitorIntervalHours !== null) { sets.push("monitor_interval_hours = ?"); params.push(monitorIntervalHours); }
    if (lastMonitorAt !== null) { sets.push("last_monitor_at = ?"); params.push(lastMonitorAt); }
    if (publishTimeSlots !== null) { sets.push("publish_time_slots = ?"); params.push(publishTimeSlots); }
    if (ratio !== null) { sets.push("ratio = ?"); params.push(ratio); }
    if (hashtagsJson !== null) { sets.push("hashtags_json = ?"); params.push(hashtagsJson); }
    if (privacyLevel !== null) { sets.push("privacy_level = ?"); params.push(privacyLevel); }
    sets.push("updated_at = ?"); params.push(ts);
    params.push(matrixId);
    this.db.prepare(
      `UPDATE matrix_auto_publish_config SET ${sets.join(", ")} WHERE matrix_id = ?`
    ).run(...params);
  } else {
    this.db.prepare(`
      INSERT INTO matrix_auto_publish_config

    this._updatePipeline(pipeline.id, { status: "failed", failReason: "缺少 profile_id" });
    return true;
  }

  if (!cfg) {
    this._updatePipeline(pipeline.id, {
      status: "failed", failReason: "缺少 matrix_auto_publish_config 配置",
    });
    this._emitChange();
    return true;
  }

  // daily_limit 从矩阵配置查（不再查 creator_profile_bindings）
  const dailyLimit = cfg?.dailyLimit || 3;
  const todayPublished = this._countTodayPublishedByProfile(profileId);
  if (todayPublished >= dailyLimit) {
    return false;
  }

  // ... 其余逻辑（混剪、创建 material、创建 publish_job）不变
  // 但 cfg 字段访问改为驼峰：cfg.presetId, cfg.hashtagsJson, cfg.privacyLevel, cfg.publishTimeSlots
  const material = this.store.createTkMaterial({
    filePath: remixTask.outputUrl,
    title: remixTask.title || "自动发布视频",
    hashtags: Array.isArray(hashtags) ? hashtags : [],
    privacyLevel: cfg?.privacyLevel || "public",
    category: "auto-publish",
  });
  // ...
}
```

## 7. 风险与注意事项

### 7.1 迁移幂等性
迁移脚本必须幂等（`INSERT OR IGNORE` + 存在检查），因为服务重启会重新执行迁移块。

### 7.2 旧表暂不删
Task 11 之前保留旧表，方便回滚。但代码不再读写旧表。

### 7.3 pipeline.matrix_id 可能为空
迁移时，已有的 pipeline 记录如果 `matrix_id` 为空，排期时 `_getMatrixConfig` 返回 null → 该 pipeline 会被标记 failed。需在 Task 8 中处理：对 `matrix_id` 为空的 pending pipeline，尝试从 `creator_id` 反查 `creator_auto_publish_config.matrix_id`（旧表还在）补全。

### 7.4 一个达人被多个矩阵选中
调度器遍历矩阵配置时，同一达人的视频会被多个矩阵各自创建一条 pipeline（发到不同实例）。这是正确行为——`matrix_account_creators` 是多对多，同一达人可被不同矩阵的不同账号选中。

### 7.5 daily_limit 语义
旧 `daily_limit_per_profile`（每实例每日上限）与新 `daily_limit`（每实例每日上限）语义一致，因为一个矩阵只绑一个实例。计数逻辑 `_countTodayPublishedByProfile(profileId)` 不变。

### 7.6 监控用户名
旧配置有 `tiktok_username` 字段。新架构中，监控用户名应从 `remix_creators` 表的达人信息中提取（`_extractUsername(creator)` 方法已有）。如果达人信息中没有 TikTok 用户名，需确保 `remix_creators` 有对应字段或从 URL 提取。

### 7.7 前端兼容
前端改为矩阵列表后，原有的「对标达人列表」不再展示。如果用户仍需在自动发布 Tab 查看达人列表，可在矩阵弹窗的账号行中展示该账号选了哪些达人（通过 `matrix_account_creators` 查询）。
