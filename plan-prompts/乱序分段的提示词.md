# 视频安全分段 + AI 全局乱序 + TikTok 英文内容生成｜生产版 V3

请直接处理我本次上传的【1 个原始视频】。

用户可能同时提供【时间轴字幕】，也可能只提供视频。

必须读取：

* 原始视频文件；
* 实际媒体元数据；
* 真实帧序列及帧时间戳；
* 原始音轨；
* 用户提供的时间轴字幕（如有）。

最终直接在回复中输出【1 个完整标准 JSON 对象】。

回复中只能包含 JSON 文本本身，不得包含任何解释、前言、后记、Markdown、代码块或下载链接。

本任务只执行：

1. 视频内容识别；
2. 安全分段；
3. `reorderable` 判断；
4. AI 生成全局重排顺序；
5. TikTok 英文标题与话题标签生成；
6. 基于视频中参考包款生成一段不超过 100 个英文单词的专业包袋购买经验文案。

不剪辑视频，不生成新视频，不修改原视频，不生成字幕文件，不生成其他文件。

# 一、字幕模式

## 模式 A：用户提供时间轴字幕

如果用户提供字幕：

【用户字幕是唯一字幕文本来源。】

必须：

1. 不重新执行完整 ASR；
2. 不重新生成字幕；
3. 不修改、改写、翻译或补写字幕；
4. 使用用户字幕的时间、文本和语义辅助判断分段；
5. 将每条字幕完整分配到对应 segment 的 `timeline_subtitles`；
6. 根据真实视频帧时间戳映射字幕帧号。

原始音轨仅辅助判断：

* 停顿；
* 换气；
* 静音；
* 连续讲话；
* 安全切点。

如果字幕文本与实际音频存在轻微差异：

【仍以用户字幕文本为准。】

不得为了验证字幕重新执行语音转写。

---

## 模式 B：用户未提供字幕

如果用户没有提供字幕：

【禁止执行完整语音转写，禁止生成字幕。】

只分析音频中的：

* 连续讲话区间；
* 长句或连续表达；
* 明显停顿；
* 换气；
* 句间静音；
* 讲话结束位置。

所有分段必须：

`"timeline_subtitles": []`

不得猜写人物具体说了什么。

此模式主要依据：

【讲话连续性 + 停顿/换气 + 基本画面内容】

判断安全分段。

---

# 二、核心分段规则

成功结果必须满足：

`segment_count >= 4`

即至少划分为【4 个分段】。

必须先分析完整视频，再决定实际段数。

不得预设固定段数。

内部边界优先选择：

1. 完整句子或连续表达结束；
2. 明显自然停顿；
3. 换气；
4. 句间静音；
5. 明显话题结束；
6. 产品、动作或展示阶段变化附近的安全位置。

最高原则：

【不得明显切断连续讲话。】

禁止：

* 在单词发音中间切；
* 在明显连续讲话中强切；
* 按固定秒数机械切；
* 为平均时长而切；
* 为凑够 4 段而强切；
* 仅因为画面切镜就切断连续讲话；
* 将同一条用户字幕拆到两个分段。

如果画面已经变化，但人物仍连续讲话：

【等待最近的自然停顿、换气或静音后再切。】

---

# 三、内容结构判断

## 多对象视频

如果人物依次介绍多个产品、包包、穿搭、案例或其他对象，应优先按照真实内容结构划分。

例如真实存在：

* 开场；
* 产品 1；
* 产品 2；
* 产品 3；
* 总结；

可形成对应的多个分段。

不得人为制造不存在的内容结构。

---

## 单对象视频

如果视频主要围绕同一个对象，可按照真实讲解阶段划分，例如：

* 总体展示；
* 外观设计；
* 材质；
* 五金；
* 缝线；
* 内部；
* 容量；
* 上身效果；
* 使用方式；
* 综合评价。

只能使用视频中真实存在的内容。

连续多句话如果都在讨论同一个具体要点，应尽量保留在同一分段。

不得按照：

* 每句话；
* 每条字幕；
* 每 5 秒；
* 每 10 秒；

机械分割。

目标是形成：

【相对完整、可以独立理解的内容块。】

# 四、转场语句

用户提供字幕时：

类似：

* “接下来看看这个”
* “然后是这个”
* “下面这个”
* “再来看这个”

原则上并入后一个内容块。

类似：

* “所以我很喜欢这个”
* “总的来说这个不错”
* “这就是我喜欢它的原因”

原则上并入前一个内容块。

不得生成只有连接词或过渡句的独立分段。

无字幕时，根据音频停顿、画面变化和动作结束位置保守判断。

# 五、画面分析范围

画面主要辅助判断：

* 当前正在展示哪个对象；
* 是否更换展示对象；
* 是否进入新的展示动作；
* 是否发生明显场景变化；
* 某个展示动作是否结束；
* 视频中参考包款的大致类型、结构和可见细节。

不进行不必要的复杂画面分析。

有字幕时优先级：

1. 字幕表达完整；
2. 音频停顿或换气；
3. 内容主题；
4. 画面连续性；
5. 时长均匀程度。

无字幕时优先级：

1. 连续讲话是否结束；
2. 停顿、换气或静音；
3. 画面内容变化；
4. 动作完整性；
5. 时长均匀程度。

不得为了时长均匀破坏前四项。

# 六、至少四段安全门槛

成功结果必须：

`segment_count >= 4`

因此至少需要找到【3 个合理内部安全边界】。

如果无法找到 3 个不会明显切断讲话、字幕或关键动作的合理边界，必须返回失败：

`"status": "failed"`

`"segment_count": 0`

`"segments": []`

错误码：

`INSUFFICIENT_SAFE_BOUNDARIES_FOR_FOUR_SEGMENTS`

不得为了返回 success 强行切成 4 段。

---

# 七、第一段固定

这是硬性规则。

第一段必须：

```json
{
  "original_order": 1,
  "reorderable": false,
  "recommended_position": 1
}
```

第一段始终固定在最终视频第一位。

必须满足：

`recommended_order[0] == "seg_001"`

第一段不参与任何调序。

---

# 八、其余分段的 reorderable 判定

从第 2 段开始，包括原视频最后一段：

【全部根据实际逻辑判断是否允许调序。】

不再强制固定最后一段。

如果某段满足以下条件，可设置：

`"reorderable": true`

条件：

1. 内容本身相对完整；
2. 大致可以独立理解；
3. 不存在强烈必须承接上一段的关系；
4. 不存在强烈必须引出下一段的关系；
5. 移动后不会产生明显事实错误；
6. 不存在强烈因果关系；
7. 不存在无法脱离上下文的指代；
8. 动作不要求严格连续；
9. 调换后虽然叙事顺序可能不同，但普通观众仍能理解。

以下情况应：

`"reorderable": false`

例如：

* 明确依赖上一段的动作；
* 明确回答上一段提出的问题；
* 强因果关系；
* 强时间顺序；
* 明确的前后指代；
* 句意必须连续；
* 未完成的比较结构；
* 单纯 transition；
* 移动后会明显让观众不知道正在说什么。

对于轻微依赖：

【不要过度保守。】

只要移动后不会造成明显逻辑错误，可以允许：

`"reorderable": true`

目标不是保持原视频叙事，而是：

【在基本可理解的前提下，为后续重剪提供足够大的顺序变化。】

# 九、AI 全局重排

禁止程序后续随机打乱分段。

本任务必须由 AI 直接生成最终推荐顺序：

`recommended_order`

例如：

```json
"recommended_order": [
  "seg_001",
  "seg_005",
  "seg_003",
  "seg_006",
  "seg_002",
  "seg_004"
]
```

以上只是格式示例，不得复制。

---

## 9.1 重排核心目标

AI 必须在以下两个目标之间平衡：

### 目标 A：逻辑基本成立

最终顺序不得造成：

* 明显因果倒置；
* 严重指代错误；
* 未介绍对象就直接使用强指代；
* 动作明显倒放式衔接；
* 问题和回答完全错位；
* 总结出现在相关主体内容之前且明显不合理；
* 依赖前文的信息完全丢失。

允许：

* 内容顺序与原视频明显不同；
* 先看某个细节，再看另一个细节；
* 多个并列特点改变展示顺序；
* 多个独立产品改变介绍顺序；
* 材质、五金、容量、上身等并列模块交换位置；
* 轻微的口语衔接不完美。

目标是：

【逻辑不会特别混乱】

而不是：

【必须像原视频一样顺畅。】

---

### 目标 B：尽可能充分乱序

在满足基本逻辑的情况下：

【优先最大化新顺序与原顺序之间的差异。】

不要只交换两个分段。

不要只交换相邻两个分段。

不要生成：

`1,2,3,5,4,6`

这类变化极小的顺序，除非确实没有其他安全方案。

应尽量：

* 移动多个可调序分段；
* 让可移动段跨越多个原始位置；
* 减少可移动段停留在原位置；
* 减少原本相邻的段在新顺序中继续相邻；
* 避免只进行一个 pair swap；
* 避免简单旋转一格；
* 避免几乎保持原序；
* 优先产生明显的新内容节奏。

---

# 十、重排算法原则

内部应采用：

【约束条件下的最大位移重排】

而不是随机排列。

执行思路：

1. 第一段固定为第 1 位；
2. 找出所有 `reorderable = false` 的强依赖段；
3. 确定这些段必要的相对依赖关系；
4. 找出其余可移动段；
5. 对可移动段尝试尽可能大的跨位置移动；
6. 优先打破原始相邻关系；
7. 优先避免可移动段停留原位；
8. 在多个可行方案中选择与原顺序差异最大的方案；
9. 最后检查整体语义是否仍基本可理解。

不得使用纯随机方式决定最终顺序。

---

# 十一、充分乱序标准

如果：

`movable_segment_count >= 3`

则推荐顺序应尽量满足：

### 1. 至少移动多个段

至少应有：

`moved_segment_count >= 2`

并且在条件允许时：

【优先让大多数 reorderable=true 的分段发生位置变化。】

---

### 2. 避免仅交换两个段

如果存在 3 个或更多可移动段：

`pair_swap_only` 必须为：

`false`

不得只选择两个段互换位置而其余全部不动。

---

### 3. 减少原位段

在不破坏明显逻辑的前提下：

尽量使：

`same_position_count`

越低越好。

第一段固定造成的原位不计入乱序失败。

---

### 4. 增加平均位移

对每个可移动段：

`position_displacement = abs(original_order - recommended_position)`

AI 应优先选择：

【总位移更大的安全方案。】

---

### 5. 打破原始邻接

原视频中：

`seg_002 → seg_003`

如果二者没有强依赖，不应因为原来相邻就继续保持相邻。

应尽量降低：

`preserved_original_adjacency_count`

---

# 十二、无法充分乱序时

如果内容存在大量强依赖关系，导致无法大幅调序：

不得强行制造逻辑错误。

此时：

1. 保留必要依赖；
2. 对剩余可移动内容尽可能重排；
3. `reorder_strength` 根据实际结果填写；
4. 在 `reorder_note` 中简短说明限制原因。

不能为了达到 high 而破坏明显逻辑。

---

# 十三、每段新增排序字段

每个 segment 必须新增：

```json
"recommended_position": 0,
"position_displacement": 0
```

其中：

`recommended_position`

表示该 segment 在 AI 推荐重排后的最终位置。

第一段必须：

`recommended_position = 1`

`position_displacement`

计算：

`abs(original_order - recommended_position)`

例如：

原位置 5，推荐位置 2：

`position_displacement = 3`

---

# 十四、顶层新增 reorder_plan

JSON 顶层必须增加：

```json
"reorder_plan": {
  "strategy": "ai_global_reorder",
  "first_segment_locked": true,
  "recommended_order": [],
  "movable_segment_count": 0,
  "moved_segment_count": 0,
  "same_position_count_excluding_first": 0,
  "total_position_displacement": 0,
  "preserved_original_adjacency_count": 0,
  "pair_swap_only": false,
  "reorder_strength": "high",
  "reorder_note": ""
}
```

---

## 字段说明

### strategy

固定：

`"ai_global_reorder"`

表示最终顺序由 AI 根据内容逻辑生成，不使用随机排序。

---

### first_segment_locked

固定：

`true`

---

### recommended_order

必须包含全部 `segment_id`。

每个 segment：

* 只能出现一次；
* 不得遗漏；
* 不得重复。

第一项必须：

`"seg_001"`

---

### movable_segment_count

统计：

`reorderable == true`

的 segment 数量。

---

### moved_segment_count

统计：

`recommended_position != original_order`

的可移动 segment 数量。

---

### same_position_count_excluding_first

统计除第一段外仍处于原位置的 segment 数量。

该数值在逻辑允许时应尽量低。

---

### total_position_displacement

所有 segment 的：

`position_displacement`

之和。

在多个逻辑可接受方案中：

【优先选择该值更大的方案。】

---

### preserved_original_adjacency_count

统计原视频中相邻的两个 segment，在推荐顺序中仍然保持：

【相同前后方向并继续相邻】

的数量。

在不破坏强逻辑关系的情况下，该值应尽量低。

---

### pair_swap_only

如果最终变化只是两个 segment 互换，而其他位置全部保持不变：

`true`

否则：

`false`

当 `movable_segment_count >= 3` 时：

应尽量保证：

`pair_swap_only = false`

---

### reorder_strength

枚举：

* high
* medium
* low

判断原则：

#### high

多数可移动段都发生明显位置变化，并且新顺序与原顺序差异明显。

#### medium

多个分段发生变化，但受逻辑限制仍保留较多原结构。

#### low

只有少量安全移动空间，新顺序与原顺序比较接近。

不得为了填写 high 而制造不合理顺序。

---

### reorder_note

使用简短英文说明推荐顺序的重排逻辑。

例如可以表达：

* reordered independent feature sections while preserving dependencies
* moved parallel product demonstrations apart to increase sequence variation
* limited reordering because several segments depend on previous context

不得输出长篇分析。

---

# 十五、字幕字段

用户提供字幕时：

`timeline_subtitles` 必须完全来自用户字幕。

每条字幕：

```json
{
  "subtitle_id": "",
  "speaker_id": "",
  "start_frame": 0,
  "end_frame": 0,
  "start_time": "00:00:00.000",
  "end_time_exclusive": "00:00:00.000",
  "text": "",
  "confidence": "high"
}
```

规则：

* `text` 保持用户原文；
* 不重新听写；
* 不翻译；
* 不补写；
* 不改写；
* 不拆分字幕。

如果字幕跨越候选分段边界：

【移动分段边界，不拆字幕。】

用户没有字幕时：

`"timeline_subtitles": []`

---

# 十六、媒体元数据与帧规则

必须读取真实媒体数据。

不得估计：

* 视频时长；
* 帧率；
* 总帧数；
* 帧号；
* 帧时间戳。

所有帧号从 0 开始。

`start_frame` 与 `end_frame` 均包含端点。

原始分段必须满足：

第一段：

`start_frame = 0`

相邻原始分段：

`后一段 start_frame = 前一段 end_frame + 1`

最后一个原始分段：

`end_frame = frame_count - 1`

原始 segments 数组始终按照：

【原视频时间顺序】

输出。

注意：

【不得按照 recommended_order 改变 segments 数组自身顺序。】

真正的新顺序只通过：

* `recommended_position`
* `reorder_plan.recommended_order`

表达。

这样可同时保留：

【原始时间结构 + 推荐重剪顺序】

# 二十、validation

成功结果必须检查：

* `segment_count == segments.length`；
* `segment_count >= 4`；
* segments 始终按照原视频时间顺序；
* `segment_id` 连续；
* `original_order` 连续；
* 第一段 `reorderable == false`；
* 第一段 `recommended_position == 1`；
* 第一段必须位于 `recommended_order[0]`；
* 最后一段不再强制固定；
* 所有分段都有布尔 `reorderable`；
* 所有 `recommended_position` 唯一；
* `recommended_order` 包含全部 segments；
* 不遗漏；
* 不重复；
* `recommended_order` 与 `recommended_position` 完全一致；
* 第一帧为 0；
* 最后一帧为 `frame_count - 1`；
* 无漏帧；
* 无重叠；
* 无明显连续讲话中切断。

成功时必须：

```json
"frame_gap_count": 0,
"frame_overlap_count": 0,
"mid_sentence_cut_count": 0,
"unsafe_audio_boundary_count": 0
```

用户提供字幕时：

```json
"subtitle_cross_segment_count": 0,
"duplicate_subtitle_count": 0,
"unassigned_speech_count": 0
```

无字幕时上述字段同样填写 0。

# 二十一、执行流程

内部严格按以下顺序执行：

1. 读取真实媒体元数据；
2. 读取真实帧序列与帧时间戳；
3. 判断是否提供字幕；
4. 有字幕直接使用；
5. 无字幕禁止完整转写；
6. 分析连续讲话、停顿、换气和静音；
7. 简单分析人物、产品、动作和画面；
8. 找到至少 5 个安全内部边界；
9. 形成至少 6 个分段；
10. 将所有边界对齐真实视频帧；
11. 完整覆盖全部帧；
12. 第一段强制 `reorderable = false`；
13. 判断其余所有分段的 `reorderable`；
14. 建立段落依赖关系；
15. 由 AI 生成多个候选重排方案；
16. 排除存在明显逻辑错误的方案；
17. 在剩余方案中选择与原顺序差异最大的方案；
18. 尽量移动多数可移动段；
19. 尽量减少原位置段；
20. 尽量减少原始相邻关系；
21. 避免仅交换两个分段；
22. 输出 `recommended_order`；
23. 计算每段 `recommended_position`；
24. 计算 `position_displacement`；
25. 生成 `reorder_plan` 统计数据；
26. 生成英文 TikTok title；
27. 生成英文 hashtags；
28. 生成 ≤100 词英文 `expert_buying_note`；
29. 完成 validation；
30. 输出单个 JSON 对象。

# 二十二、禁止执行

禁止：

* 完整 ASR；
* 逐字语音识别；
* 重新生成字幕；
* 复杂说话人识别；
* 逐字音素对齐；
* 为验证字幕再次转写；
* 按固定秒数切分；
* 纯随机打乱；
* 仅随机交换两个分段；
* 为制造乱序而破坏明显语义；
* 猜测字幕；
* 猜测帧号；
* 猜测媒体元数据；
* 猜测品牌；
* 猜测具体型号；
* 猜测无法确认的材质或工艺。

# 二十三、失败规则

出现以下情况必须失败：

* 视频损坏；
* 无法读取真实媒体元数据；
* 无法获得可靠帧序列；
* 无法获得所需帧级时间信息；
* 无法找到至少 3 个合理内部安全边界；
* 无法形成至少 4 个安全分段。

失败时：

```json
"status": "failed",
"segment_count": 0,
"segments": []
```

无法形成至少 4 段时：

`INSUFFICIENT_SAFE_BOUNDARIES_FOR_FOUR_SEGMENTS`

如果只能进行有限程度的调序：

【不得因此失败。】

应正常输出：

`status = success`

并将：

`reorder_strength`

设置为：

`medium`

或：

`low`

同时在 `reorder_note` 中说明逻辑依赖限制。

# 二十四、最终输出要求

最终回复必须：

1. 只包含一个标准 JSON 对象；
2. 可以被标准 JSON 解析器直接解析；
3. 不使用 Markdown 代码块；
4. 不输出任何 JSON 外文字；
5. 不生成文件；
6. 不提供下载链接；
7. 不输出 TXT；
8. 不输出 Markdown；
9. 不输出图片；
10. 不输出视频；
11. 不输出 ZIP；
12. 不输出分析报告；
13. 不输出中间过程。

最终成功结果必须满足：

`segment_count >= 4`

`segments[0].reorderable == false`

`segments[0].recommended_position == 1`

`reorder_plan.recommended_order[0] == "seg_001"`

注意：

【仅第一段永久固定。】

原视频最后一段与其他中间段一样：

【根据实际逻辑判断是否允许移动。】

AI 必须直接提供最终推荐乱序：

`reorder_plan.recommended_order`

后续程序应直接按照该顺序重组视频：

【不要再次随机打乱。】

在逻辑仍基本可理解的前提下：

【优先让多个可移动段发生明显位置变化，使最终顺序与原视频顺序具有足够大的差异。】
