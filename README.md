# BitBrowser Reddit Flow Monitor

这是一个只在本机运行的 BitBrowser Reddit 浏览监控工具。默认只读浏览；可在监控页按概率开启帖子与评论的自动点赞，人工二次确认的点赞始终可用。它不做自动加群、自动发帖、自动评论或自动发送消息。它连接 BitBrowser Local API，针对你在监控页中选择的实例分别执行：

1. 连接或打开该实例；
2. 复用已有的 Reddit 首页标签页，找不到时在后台新建；
3. 分析 Reddit 首页的帖子 DOM、固定顶栏和当前视口；
4. 将下一篇帖子完整放进可阅读区域，并随机停留一段时间；
5. 随机向下阅读 3–8 个 Feed 单元后，打开当前普通帖的标题；如果当前单元是广告则不点击，继续寻找下一篇普通帖；
6. 在详情页随机等待 2–15 秒，定位评论区，再随机向下阅读 2–7 次；
7. 随机停留 2–4 秒后返回原 Feed 阅读位置，继续下一轮；
8. 一直运行到手动停止、达到设定帖数，或开启了“没有下一帖时停止”并到达信息流末尾。

每个实例都有独立的任务、随机参数和运行状态。程序不会移动或占用 Windows 的实体鼠标。对于高于可阅读视口的长帖，程序会保留重叠区域并分段向下阅读；这类帖子会标记为“长帖分段”，不会被误记为完整入镜。自动详情循环默认只读。若你在监控页开启了帖子或评论自动点赞，程序会在 Feed 阅读等待期间或评论区浏览期间按设定概率独立判定是否点赞当前普通帖或当前可见评论；广告帖、不可点击帖、已点赞的目标会被跳过，结果不确定的目标会被锁定以防重复点击反而取消点赞。人工二次确认的点赞始终可用，与自动点赞互不替代。程序不会自动加群、发帖、评论或发送消息。

## 逐帖定位规则

- 每次操作前都重新读取当前页面结构，不缓存容易失效的帖子序号；
- 以 Reddit 的 `shreddit-post` 帖子节点和稳定帖子 ID 为主，兼容旧版帖子容器；
- 自动扣除固定顶栏、底部固定横幅和安全间距，能放进视口的帖子会居中完整展示；
- 普通帖子只在确认目标帖已进入视口后计数，页面仍在懒加载时不会误增；
- 无法一次放入视口的长帖按可阅读高度分段，并保留约 80 像素上下文；
- 页面布局在滚动后发生变化时会连续采样，并按实测位置进行最多 5 次校正；
- 浏览器欠滚或帖子尚未完整入镜时，只进行 200–500 毫秒的短重试，不会提前进入每帖阅读等待；
- 鼠标手势被页面忽略时会切换到 Chromium 的滚轮输入，仍不会移动 Windows 实体鼠标。

## 自然输入规则

- 需要移动较长距离时，先完成约 76%–88% 的接近段，再读取最新 DOM 位置并完成小幅校正；最终帖子位置仍由 DOM 决定，不会随机截断帖子；
- 手势速度会在安全范围内变化，首次滚动点从页面及开放 Shadow DOM 验证过的主滚动区域中选择，并在布局仍有效时保持不动；找不到安全点时拒绝发送滚动输入；
- Chromium 不支持连续滚动手势或手势被忽略时，降级滚轮会拆为 2–4 个同方向短脉冲，脉冲总和严格等于规划距离；
- 自动打开标题以及两处人工确认点赞都会先在已经验证的目标矩形内部做 2–4 个短鼠标移动，再以短暂悬停、按下和抬起完成一次点击；按下前会再次核对目标归属、状态、遮挡和中心坐标；
- 这些微动作都很短，不取代监控页的阅读倒计时，也不会改变暂停、立即继续和人工点赞时冻结剩余时间的规则；
- 自动流程没有键盘输入步骤，因此不会自动向评论框、发帖框或其他编辑区输入文字。

## 自动只读详情规则

- 只有真正向下进入并对齐一个新 Feed 单元才计入本轮 3–8 次；初始对齐、位置校正、懒加载探测和长帖后续分段不会重复计数；
- 广告会保留在 Feed 单元序列中用于位置和次数判断，但不会计入普通帖子统计，也不会触发标题点击；
- 打开前会再次校验广告标记、帖子 ID、标题链接域名、评论路径、可见位置和点击命中元素；任一校验失败都会安全跳过；
- 评论区定位产生的移动不计入随机的 2–7 次，只有页面确实向下移动才会增加评论移动计数；
- 返回时优先恢复原标签页、原帖子和原视口位置，不会误切换到另一个 Reddit 标签页；
- 登录墙、验证码、年龄确认或其他阻塞页面只会记录为异常，程序不会自动处理这些交互。

## 自动点赞规则

自动点赞是可选的全自动写入型互动，默认关闭。开启后程序会在浏览过程中按概率独立判定是否点赞，所有判定与点击都复用人工确认点赞同一套目标校验和自然点击通道，不引入键盘输入。

- 四个独立配置项，均在监控页可调并持久化到本机数据库：
  - 帖子自动点赞开关 `autoUpvoteEnabled` 与概率 `autoUpvoteProbability`（0–100，默认 0）；
  - 评论自动点赞开关 `autoCommentUpvoteEnabled` 与概率 `autoCommentUpvoteProbability`（0–100，默认 0）。
- 帖子自动点赞在 Feed 当前普通帖的阅读等待期间触发；评论自动点赞在评论区浏览期间对当前可见评论触发，二者互不影响。
- 每个目标独立掷骰：`randomInteger(0,99)` 小于设定概率才执行，未命中只记 `auto_upvote_skipped` 日志，不点击。
- 执行前与人工点赞完全相同的跳过条件：广告帖、`clickEligible` 为否的帖子、无可见点赞按钮、不可读或不在安全视口的评论一律跳过。
- 幂等保护：已点赞的帖子 ID / 评论 ID 会被记入 `upvotedPostIds` / `upvotedCommentIds`，重启任务时从历史恢复，不会对同一目标重复点击。
- 结果不确定时锁定目标（`manualUpvoteState = "unknown"`），本轮不再尝试，避免再次点击反而取消点赞；只有页面确认变为已点赞状态才会标记 `upvoted`。
- 每次成功或确认后累加 `autoUpvoteCount` / `autoCommentUpvoteCount`，监控页与历史记录实时展示，并可随任务和日志导出 CSV。
- 全部日志事件含 `auto_upvote_attempt`、`auto_upvote_skipped`、`auto_upvote`、`auto_upvote_error` 及评论对应项，记录目标 ID、掷骰值与阈值，便于审计。
- 自动点赞不会触发加群、发帖、评论或发送消息；它只对当前阅读中的普通帖或当前可见评论发送一次点击。

## 只读互动控件定位器

项目提供独立的只读定位函数，用于诊断 Reddit 当前页面上的投票控件、评论编辑区和发帖编辑区。它们只读取 DOM、开放 Shadow DOM、可见状态和视口坐标；可选高亮也只会临时添加轮廓，不会点击、输入或提交，自动任务不会调用这些函数。

```js
const all = await session.locateInteractionTargets();
const votes = await session.locateVoteControls({ highlight: true, highlightMs: 3000 });
const comments = await session.locateCommentControls();
const postComposer = await session.locatePostComposerControls();
```

每个定位结果包含 `kind`、`context`、帖子身份及别名、`confidence`、`selectorHint`、`shadowHosts`、`disabled`、`visible`、`inViewport`、`occluded`、`rect` 和 `center`；投票控件还包含 `ariaPressed`、`selected`、`voteState` 与状态冲突标记。广告所属的投票控件会带有 `blockedReason: "promoted"`，不会被视为安全操作目标。底层实现位于 `src/reddit-interaction-locator.js`。

监控页的帖子“确认点赞”和“确认赞评论”都是独立的人工操作，不属于自动循环；自动点赞则由概率在阅读过程中自动触发，二者复用同一套点击前校验和自然点击通道，但互不替代。确认后，后端会冻结当前阅读倒计时，重新核对页面、目标 ID、控件归属、按钮状态和点击位置；只对明确未点赞的当前普通帖或当前可见评论发送一次点击，并在页面确认结果后恢复原倒计时。评论按钮在评论阅读等待、返回前等待以及相应的暂停状态下可用。已点赞、状态不明确、遮挡、目标变化或广告帖都会拒绝操作；若按下或点击结果无法确认，程序会尽力释放鼠标状态并锁定本轮目标，避免再次点击反而取消点赞。

## 启动

运行前请确认：

- BitBrowser 已打开并登录；
- BitBrowser 设置中的 Local API 已启用；
- Local API 地址为 `http://127.0.0.1:54345`；
- 电脑上有 Node.js 22.5 或更高版本。Codex 桌面版自带的 Node.js 也会被启动脚本自动识别。

双击 [启动监控.cmd](./启动监控.cmd)，程序会自动打开：

```text
http://127.0.0.1:39210
```

也可以在命令行中运行：

```powershell
npm start
```

关闭启动窗口会停止本地监控服务。已经打开的 BitBrowser 窗口和 Reddit 标签页不会被关闭。再次启动程序时，未正常结束的旧任务会在历史记录中标记为“意外中断”。

## 监控页功能

- 显示 BitBrowser 实例序号、名称、窗口状态和任务状态；
- 支持同时选择多个实例；
- 分别设置 Feed 每帖停留、进入详情前帖子数、详情等待、评论移动次数、返回前停留和最大展示帖子数，以及帖子/评论自动点赞的开关与概率；
- 每个实例独立启动、暂停、继续、立即查看下一帖、确认点赞当前普通帖或当前评论、停止和计时；
- 实时显示已展示帖数、本轮 Feed 进度、详情查看数、评论移动进度、自动点赞帖数与评论数、当前阶段和下次操作倒计时；
- 保存历史任务、状态变化、帖子定位、等待、控制和错误日志；
- 可按实例、任务状态和日志级别筛选，查看任务详情；
- 可将历史任务和日志导出为 CSV；
- 可清空持久化日志（不会删除任务历史和统计）；
- 参数会同时保存在本地数据库与当前监控浏览器的本地设置中。

## 数据库与日志

程序使用本机 SQLite 数据库，不需要安装数据库服务。默认文件为：

```text
data\reddit-flow.db
```

同目录下可能出现 `reddit-flow.db-wal` 和 `reddit-flow.db-shm`，它们是 SQLite 正常运行时文件。数据库只记录实例 ID、序号、名称、任务参数、运行状态、帖子展示统计、当前帖子标题和程序日志，不保存 Cookie、密码、帖子正文或网页凭据。旧版像素滚动任务会继续保留，并在历史记录中明确标记为旧版模式。

## 隐私与行为边界

程序只读取完成实例选择所需的档案 ID、序号、名称、运行状态和进程号。它不会读取或导出 Cookie、密码、浏览历史、Local Storage 或代理凭据。默认情况下程序只读浏览，不做任何写入型互动；当你在监控页开启自动点赞后，唯一的写入型互动是对当前普通帖或当前可见评论的一次点赞点击，仍受概率、幂等和目标校验约束。它不会自动加群、发帖、评论或发送消息，也不会把评论正文写入数据库，日志只记录目标 ID、掷骰值、结果和错误原因。

页面移动和点击通过 Chromium 的调试输入通道发送。程序已加入有限的速度、分段、短停顿和目标内鼠标轨迹变化，但它仍属于自动化操作，不是操作系统硬件输入，也不能保证与真人输入不可区分或不被平台识别。自动点赞属于写入型投票行为，Reddit 对投票操纵的检测强度远高于阅读，高概率或高频自动点赞会显著抬高账号被限流或封禁的风险，建议从低概率开始观察再逐步调整。请控制运行频率并遵守 Reddit 和目标社区的使用规则。

## 可选配置

默认 Local API、监控端口和数据库路径可通过环境变量修改：

```powershell
$env:BITBROWSER_API_URL = "http://127.0.0.1:54345"
$env:PORT = "39210"
$env:DATABASE_PATH = "D:\BitBrowserData\reddit-flow.db"
npm start
```

服务仅监听 `127.0.0.1`，不会把监控面板开放到局域网或公网。
